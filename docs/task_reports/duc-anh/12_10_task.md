#### B3. Phân tích chất lượng – efficiency

1. **Nhẹ nhất & Nhanh nhất:** E0 (Custom CNN) — 397K params, 1.53 MiB, 13.1 ms latency. Nhưng Macro-F1 chỉ 19.29% — không dùng được thực tế.
2. **Tối ưu nhất:** E4 (MobileNetV2 + CutMix) — Macro-F1 cao nhất (81.51%), cùng 2.26M params và 8.86 MiB như E1, latency ~24.9 ms. CutMix cải thiện +1.55% F1 mà không tăng inference cost.
3. **Nặng nhất:** E3 (ResNet18) — 11.19M params (~4.9× E4), 42.77 MiB, latency chậm nhất 28.67 ms. Macro-F1 74.88% thấp hơn MobileNetV2.
4. **Khuyến nghị triển khai:** E4 là mô hình tốt nhất nhóm (cân bằng chất lượng, kích thước và tốc độ).

**1. PyTorch local chạy CPU mode:**
- Môi trường Conda local không có bản build CUDA.
- Xử lý: benchmark được thực hiện trên CPU với cùng protocol chuẩn (warmup=20, timed=100, batch=1, `inference_mode`). Ghi rõ thiết bị đo trong `environment.json` và Task Report.

**2. Checkpoint E0, E1, E2, E4 chưa có local:**
- Checkpoint E0–E2 do Thuận/Kiệt thực hiện trên môi trường riêng; E4 file `.pt` không commit lên GitHub (đúng quy định).
- Xử lý: Script đo params, model size và latency từ kiến trúc model thực tế (đúng config và freeze policy). Với model kiến trúc giống nhau (weights khác nhau), FLOPs, parameter count và latency inference là đồng nhất.
- Khi có file `.pt` từ Drive chung: chỉ cần đặt vào đúng thư mục `outputs/checkpoints/<EXP>/seed_42/best.pt` và chạy lại `python scripts/benchmark_efficiency.py --device cpu` để cập nhật cột `checkpoint_loaded=True`.

**3. Khác biệt Unicode khi in console Windows:**
- Lỗi `UnicodeEncodeError: 'charmap'` với ký tự unicode trên Windows `cp1252`.
- Xử lý: Thay thế bằng ASCII (`->`, `+/-`) trong console output; file CSV và JSON vẫn dùng UTF-8 chuẩn.
